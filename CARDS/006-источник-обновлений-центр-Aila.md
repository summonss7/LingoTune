## Задача
Источник обновлений по умолчанию — центр Aila (манифест v2), GitHub Releases — резерв; явная «последняя версия»

Контекст: план «Центр обновлений Aila» (пожелание Артёма, карточка
scheduler-056; канон — D:\Scheduler\UPDATES-SYSTEM.md, разделы 3–4).
LingoTune уже умеет самообновляться (app/lib/services/update_service.dart:
GitHub Releases + опция своего URL манифеста в Настройках). Переводим на
семейный канал — манифест
`https://aila.skillcoin.pp.ua/updates/lingotune/manifest.json` (формат v2 —
см. UPDATES-SYSTEM.md), GitHub остаётся фолбэком на случай недоступности Aila.
Фундамент канала — карточка aila-163; своя часть делается независимо
(клиент degrade gracefully: нет манифеста — молча работаем как есть).

Шаги:
1. update_service.dart: дефолтный источник — манифест Aila (поддержка формата
   v2: versionName, versionCode, notes, assets[].sha256); GitHub Releases —
   автоматический резерв, если манифест недоступен. Существующую настройку
   «Источник обновлений» сохранить (ручной URL приоритетнее дефолта).
2. Сравнение версий — по versionCode (у GitHub — по тегу релиза), явный
   статус «✓ У вас последняя версия» при отсутствии обновлений.
3. Сверка sha256 скачанного APK (если поле есть).
4. Publish-скрипт релиза (рядом со сборочными build_apk_*.ps1): публикует
   свежий APK из builds/ в центр Aila (node D:\Scheduler\tools\publish-update.cjs
   lingotune или эндпоинт из aila-163) И создавать GitHub-релиз как сейчас —
   один скрипт, оба канала.
5. Живая проверка: опубликовать текущую 5.10.0, телефон отвечает «у вас
   последняя версия»; на подменённом манифесте с большей versionCode — баннер
   и установка.

Правила проекта (обязательны):
- перед серьезными изменениями делать копию проекта нажимая на backup.bat
- после выполнения задачи делать коммит автоматически (с осмысленным сообщением коммита) и пуш на гитхаб
- обновлять документацию после изменений (README и т.п., если задача её касается)
- если в проекте есть тесты или сборка — прогнать их после изменений и описать результат в отчёте
- если в проекте есть сборка apk то собирать всегда в builds с указанием версии и типа сборки debug, realise...
- соблюдать общий стандарт программирования CODING-STANDARD.md в корне проекта (канон — D:\Scheduler\CODING-STANDARD.md)
- после каждой правки проекта пополнять CHANGELOG.md в его корне: запись обязательно с датой и временем НАЧАЛА и ОКОНЧАНИЯ работы — что изменено, как проверено, коммит; новые записи дописываются в конец файла
- временные файлы после работы удалять, рантайм-артефакты держать в .gitignore (не в коммите)
- найденная проблема: несерьёзная — устранить сразу, серьёзная — отдельная карточка в CARDS/ на устранение
- все служебные сообщения, уведомления писать в чат Артему в приложении Aila закладка "Хаб ИИ"
